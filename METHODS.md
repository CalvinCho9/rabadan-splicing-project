# METHODS

Full reproducible methodology for the Rabadan HLA alternative-splicing project, in pipeline order. Every threshold and function name below was read directly out of the scripts in this repo (paths and line-level logic cited inline) — nothing here is summarized from memory. Where a step happens upstream of this repo (reference construction, alignment, HLA typing), that is stated explicitly and flagged as **outside this repo / not verified here**.

Canonical folder layout and run order are also documented in `README_FOR_CLAUDE.md`; this file goes one level deeper into the actual math and code.

---

## 0. Upstream (outside this repo — described, not re-run)

None of the following steps are implemented in this repository. They are described here for completeness, based on what the input file schema and the project's own notes imply, so a reader knows exactly where "documented because we ran it" ends and "assumed because it was described to us" begins.

1. **GDC region slicing.** Raw TCGA-BRCA (and pan-cancer) BAM files were sliced to the MHC/HLA region on chr6 before realignment. **Not verified in this repo** — no slicing script or config is present here.
2. **Per-patient personalized reference construction + STAR alignment.** For each patient, personalized HLA-A/B/C allele contigs were built from that patient's own HLA genotype (rather than aligning to a generic reference), and STAR aligned that patient's reads against their own two-allele personalized contigs, producing one `SJ.out.tab`-style splice-junction file per sample × allele (`background_method.pdf` panel A, step 1, generated by `make_background_figures.py:34`: *"STAR SJ.out.tab per sample x allele (2 files/sample: allele 1, allele 2)"*). **Not verified in this repo** — the reference-construction and alignment code is not present here. `OVERNIGHT_LOG.md:110-120` documents that Phase 1 of this project had to *empirically infer* a property of that upstream step (whether HLA-B/C personalized contigs were already reverse-complemented at construction time) precisely because the construction code itself is not available to inspect — see §3 below.
3. **HLA typing.** Each patient's two-field HLA-A/B/C genotype (e.g. `A*11:01`) was typed from RNA-seq, most plausibly with a tool such as arcasHLA given the paired-end RNA-seq input and the column layout of `data/gdc_sample_sheet_normal_with_hla.tsv` (`HLA-A1, HLA-A2, HLA-B1, HLA-B2, HLA-C1, HLA-C2`, one two-field call per allele copy). **This attribution to arcasHLA specifically is an inference from column shape and common practice, not confirmed by any file in this repo** — no typing-tool name, version, or invocation appears anywhere in this codebase. Flag this as an unverified assumption if it matters for a methods section.
4. **Export to the flat SJ tables this repo consumes.** The per-sample/per-allele STAR junction calls were concatenated into the headerless, tab-separated 13-column export files this repo reads directly (`data/export_BRCA_{tumor,normal}_HLA-{A,B,C}.tsv`, `data/pan_HLA-{A,B,C}_SJ_combined.tsv`). The export step itself is outside this repo, and at least one export-stage bug was caught downstream rather than upstream — see §6's `BRCA_NORMAL` mislabeling.

Everything from here on (§1 onward) is implemented and reproducible from this repo.

## 1. Input data

**Schema** (`README_FOR_CLAUDE.md:8-9`, `analyze_brca.py:89-93`, `COLUMNS`), 13 columns, tab-separated, **no header row**:

```
Cohort, Type, Barcode, Allele, Contig, First_base, Last_base, Strand,
Motif, Annotated, Uniquely_mapping, Multimapping, Overhang
```

- `Type` ∈ {`tumor`, `normal`} (lower-cased and stripped on load — `analyze_brca.py:118`).
- A patient's tumor and normal sample can share the same `Barcode`, so every per-sample grouping keys on `[Type, Barcode, Allele]`, never `[Barcode, Allele]` alone (`analyze_brca.py:95-97`).

- STAR's own per-sample/allele coordinate sort is preserved on load and never re-sorted (`analyze_brca.py:110-113`) — the cumulative-sum bucketing in §2 depends on this row order.

## 2. Per-sample derived columns

Implemented in `analyze_brca.compute_derived_columns()` (`analyze_brca.py:130-152`), reused unmodified for every gene via `hla_common.build_gene_frame()` (`hla_common.py:42-50`).

1. **`Annotated_cumsum`**: cumulative sum of the `Annotated` flag (0/1) within `[Type, Barcode, Allele]`, in the file's existing (STAR-sorted) row order. This buckets every row with the annotated junction it sits downstream of — bucket *N* means "downstream of the *N*th annotated junction in this sample/allele's transcript" (`analyze_brca.py:133-138`).
2. **`Splice_coord`**: string `"{First_base}_{Last_base}"` (`analyze_brca.py:145-147`).
3. **`Local_rate`**: a junction's `Uniquely_mapping` reads divided by the summed `Uniquely_mapping` reads of every row sharing its `[Type, Barcode, Allele, Annotated_cumsum]` bucket — i.e. how big this junction is relative to every other junction competing in the same annotated-junction "slot" (`analyze_brca.py:149-151`).
4. **`Contig_rd`**: first 11 characters of `Contig` (2-field allele id).

## 3. AS-event detection and classification

### 3a. The AS-event filter

`analyze_brca.find_as_events()` (`analyze_brca.py:158-170`):

```
Annotated == 0   AND   Local_rate > local_rate_threshold   AND   Annotated_cumsum != 0
```

- `Annotated == 0`: the junction is a *novel* (non-reference) splice call.
- `Local_rate > local_rate_threshold`, **default 0.10** (CLI: `--local-rate-threshold`): the novel junction must carry more than 10% of its local bucket's reads — a floor meant to exclude alignment noise/spurious low-abundance junctions.
- `Annotated_cumsum != 0`: excludes any row occurring *before* the first annotated junction in the transcript (bucket 0 has no annotated junction to compare against).

This threshold is a CLI flag specifically so it can be sensitivity-tested rather than trusted blindly (`analyze_brca.py:163-164`) — see `additional_analyses.py`'s sweep, §8 below.

### 3b. Attaching the annotated (wild-type) junction → `AS_pattern`

`analyze_brca.annotate_events()` (`analyze_brca.py:176-198`):

For each candidate event, the `Annotated == 1` row in the *same* `[Type, Barcode, Allele, Annotated_cumsum]` bucket (deduplicated, `keep="first"`, since there is exactly one annotated junction per bucket by construction) supplies `Annotated_coord`. `AS_pattern` is then built as:

```
AS_pattern = f"{Annotated_coord}->{Splice_coord}"
```

i.e. `"W1_W2->V1_V2"`. Events whose bucket has no matching annotated row are dropped with a printed warning (`analyze_brca.py:190-194`) — this should be rare/never by construction, since `Annotated_cumsum != 0` guarantees an annotated junction exists earlier in the sample's row order.

### 3c. Event classification by coordinate geometry

`analyze_brca.classify_events()` (`analyze_brca.py:206-236`). Parses `AS_pattern` as `W1_W2->V1_V2` (`W` = annotated/wild-type junction, `V` = variant/novel junction) and classifies:

| Event class | Geometric rule | Default threshold | Biological meaning |
|---|---|---|---|
| `exon5_skip` | `V1 == W1` and `V2 - W2 >= exon_skip_min_jump` | `exon_skip_min_jump = 100` (bp) | donor unchanged, acceptor jumps far downstream → the whole exon in between is skipped |
| `intron5_retention` | `V2 == W2` and `0 < V1 - W1 <= intron_retention_max_shift` | `intron_retention_max_shift = 50` (bp) | acceptor unchanged, donor shifts a few bp upstream into the intron → partial intron retention |
| `other` | neither of the above | — | everything else |

Both thresholds are CLI flags (`--exon-skip-min-jump`, `--intron-retention-max-shift`) precisely because they are coordinate-offset judgment calls, not gene-specific biological constants, and are meant to be re-checked per gene against exon-5 length rather than assumed (`analyze_brca.py:64-70`).

**These two named event classes are the specific events called out in the MHC Hammer paper (Nature Genetics)** that this analysis was built to test (`analyze_brca.py:12-18`); the classifier reproduces, in vectorized pandas, the same per-sample splicing math as the project's earlier R script (`plot_HLA-A_BRCA.R`, not part of this repo).

### 3d. Strand-aware geometry validation (Phase 1) and its per-gene verdict

**Why this was needed.** The classifier above is written in transcript-relative terms (donor = `First_base`, acceptor = `Last_base`, "downstream" = increasing coordinate) — correct only if genomic left-to-right order equals transcript 5'→3' order, i.e. plus-strand junctions. HLA-A is a plus-strand gene (~97.8% `Strand==1`); HLA-B/C are minus-strand genes (HLA-B ~97.7-97.8% `Strand==2`, HLA-C ~94.4-94.7% `Strand==2` — cited figures vary slightly by run, both from `phase1_bc_strand_check.py` output / `OVERNIGHT_LOG.md:80-84`). It was empirically confirmed that `First_base <= Last_base` holds for **every row across A/B/C, 0 violations** — i.e. coordinates are stored in genomic left-to-right order in these exports, not pre-oriented per transcript (`hla_common.py:58-61`, `OVERNIGHT_LOG.md:79-81`). So for a minus-strand junction, applying the plus-strand-oriented classifier as-is risks getting donor/acceptor backwards.

**The proposed fix — `hla_common.classify_events_strand_aware()`** (`hla_common.py:53-112`): for `Strand == 2` rows only, mirror coordinates before applying the *unchanged* geometry:

```
W1' = -W2,  W2' = -W1     (same transform for V1/V2)
```

This negate-and-swap preserves `W1' <= W2'` and re-maps "coordinate increases" to "moves further downstream along a minus-strand transcript," making the existing plus-strand-derived geometry correct for minus-strand rows too. Plus-strand rows are left untouched. `flip_minus=False` reproduces the naive (strand-blind) classification.

**Phase 1 validation methodology** (`phase1_bc_strand_check.py`, function `run_gene()` / `classifier_comparison()` / `decide_verdict()`, lines 94-239): for each of HLA-B and HLA-C, events were classified **both ways** (naive and strand-mirrored) and the two schemes were compared on which produced a materially larger, geometrically coherent count of `exon5_skip`/`intron5_retention` distinct carriers. Decision rule (`phase1_bc_strand_check.py:180-239`), evaluated **empirically per gene, not assumed from strand alone**:

- If `naive_carriers + flipped_carriers < 5` total → **`untrustworthy`** (insufficient signal to validate either scheme).
- If naive carriers exceed flipped by more than 1 → **`valid_as_is`** (no flip needed).
- If flipped carriers exceed naive by more than 1 → **`needs_direction_flipped`**.
- Otherwise (within 1 of each other) → **`untrustworthy`** (ambiguous).

**Verdict, per gene** (`outputs/PHASE1_BC_strand_check.md`):

| Gene | % minus-strand rows | Naive carriers | Flipped carriers | Verdict |
|---|---|---|---|---|
| HLA-A | ~2% (reference; not re-run by Phase 1) | — | — | (never in question — used as-is throughout) |
| HLA-B | ~97.7-97.8% | 1 | 0 | **`untrustworthy`** — only 2 candidate AS events total in the whole 935-tumor/106-normal cohort at the standard 10% local-rate threshold (vs 60 for HLA-C, ~200+ for HLA-A); traced to a real data-driven ceiling, HLA-B's maximum observed `Local_rate` in this cohort is only 12.6% (barely above the 10% detection floor) vs 52-60% for A/C — not determined whether this is real biology or a technical/reference issue (`OVERNIGHT_LOG.md:122-134`) |
| HLA-C | ~94.4-94.7% | 30 | 0 | **`valid_as_is`** — the naive (unflipped) classifier finds a coherent, A-like recurrent signal (e.g. `hla_c_03_04`'s top pattern `1273_1711->1291_1711` cleanly fits the intron5_retention geometry); the flip relabels 59/60 candidate rows to `other`, destroying the signal |

**Working explanation for the counter-intuitive HLA-C result** (`OVERNIGHT_LOG.md:110-120`, explicitly flagged there as an *inference*, not confirmed against upstream code): the personalized per-patient reference contigs for HLA-B/C were likely already reverse-complemented at reference-construction time, making `First_base`/`Last_base` in this export already transcript-oriented (same convention as HLA-A) — so the `Strand` column plausibly records the gene's known genomic strand as metadata rather than instructing a per-row coordinate transform. **This is an unverified assumption about a step outside this repo** — `OVERNIGHT_LOG.md:457-468` lists confirming it with whoever built the personalized HLA-B/C references as a top follow-up item.

**Net effect:** both HLA-B and HLA-C use the **naive (unflipped) classifier** in every downstream phase (`phase2_bc_headline.py:82`, `phase3_pancancer_descriptive.py:170`, `phase5_pancancer_matched_normal.py:203`) — HLA-C because naive was validated correct, HLA-B because naive was merely the (unvalidated) less-bad option pending more data. **`classify_events_strand_aware(flip_minus=True)` is implemented, tested, and not used anywhere in the presented results.**

**Quarantine rule that follows from this** (applied uniformly in Phases 2, 3, 5): HLA-C is presented normally; **HLA-B is quarantined** — every HLA-B output from Phase 2 onward is written under an `outputs/UNVALIDATED_HLA_B_*` prefix, excluded from `RESULTS_SUMMARY.md`, `PRESENTATION_NOTES.md`, and `figures_overview.pdf`, and carries a `*_README.md` explaining why (e.g. `outputs/UNVALIDATED_HLA_B_README.md`, generated in `phase2_bc_headline.py:139-161`).

## 4. Constitutive-annotation-artifact check (the check that caught A\*11:01)

**Question it answers:** is a recurrent AS event real, biologically variable alternative splicing, or is it just a near-universal feature of that allele's reference/transcript that carries no tumor-vs-normal information? Originally built in `diagnostic_annotation_check.py` for HLA-A\*11:01 specifically (`TARGET_ALLELE`), then generalized (allele-parametrized, same thresholds/logic) into `hla_common.top_event_penetrance()` / `hla_common.add_verdict()` / `hla_common.read_share_label()` (`hla_common.py:120-195`) and reused as-is for every gene and every later phase.

### 4a. Penetrance table

`top_event_penetrance(df, events, min_allele_samples=20)` (`hla_common.py:120-165`, mirrors `diagnostic_annotation_check.py:165-204`):

1. Restrict to alleles (`Contig_rd`) with `≥ MIN_ALLELE_SAMPLES` **(default 20)** total tumor+normal carriers.
2. For each qualifying allele, find its single most-recurrent `AS_pattern` (by distinct carrier `Barcode` count).
3. Report `Tumor_pct`/`Normal_pct` = % of that allele's own tumor/normal carriers who show that top pattern, plus `Avg_variant_local_rate_pct` = the average share of local-bucket reads the variant (novel) junction takes among its carriers.

### 4b. Verdict logic

`add_verdict(table, high=80, low=5, min_n=10)` (`hla_common.py:176-195`, identical to `diagnostic_annotation_check.py:232-252`). Gated **on penetrance alone** — read-share (`Avg_variant_local_rate_pct`) is reported as a diagnostic label, never a gate:

| Verdict | Condition |
|---|---|
| `insufficient_data` | no group (tumor/normal) has both a defined percentage and `n > 0` |
| `rare_private_event` | max penetrance across available groups `< 5%` (`LOW_PENETRANCE`) |
| `constitutive_annotation_artifact` | min penetrance across every group with usable data `≥ 80%` (`HIGH_PENETRANCE`) — present in ~everyone regardless of tumor/normal status |
| `constitutive_annotation_artifact (one group underpowered)` | one group with `n ≥ 10` (`min_n`) shows `≥ 80%` penetrance, but the other group has `n < 10` to confirm/refute |
| `real_variable_splicing_candidate` | everything else — present in some carriers, absent in others (roughly 5-80%) |

`Read_share_pattern` (`read_share_label()`, `hla_common.py:168-173`) separately labels *why* a constitutive call is constitutive: `≥ 50%` (`DOMINANT_SHARE`) variant-junction read share → "looks like a coordinate/GTF mismatch"; `< 50%` → "annotated junction stays dominant — novel is a minor, fairly fixed fraction."

### 4c. The A\*11:01 result

From `diagnostic_annotation_check.py` / `ANNOTATION_ARTIFACT_NOTE.md`: `hla_a_11_01`'s top pattern (`2365_2806->2383_2806`, classified `intron5_retention`) is present in **96.7% of tumor carriers (118/122)** and **100% of normal carriers (19/19)** → `constitutive_annotation_artifact`. The read-share check (`variant_vs_annotated_share()`, `diagnostic_annotation_check.py:117-139`) shows the **annotated** junction remains the majority isoform at ~72% of local reads on average (variant ~25-30%), ruling out a simple reference-coordinate swap and pointing instead to a real, fixed, universal *minor* splice isoform of A\*11:01's reference transcript — not tumor biology. **Consequence:** `hla_a_11_01` is the default value of `analyze_brca.py`'s `--exclude-alleles` flag (`analyze_brca.py:858-865`) — excluded from the headline and per-allele comparisons only, never from descriptive/overview outputs, and both the excluded and unfiltered numbers are always written to CSV so the effect of exclusion is auditable (`analyze_brca.py:900-920`).

**No B or C allele was flagged as a constitutive artifact in the BRCA cohort** by this same check (Phase 1: `outputs/table_phase1_penetrance_HLA_B.csv` / `_HLA_C.csv`). Phase 2 re-derives this check per gene anyway (`phase2_bc_headline.py:60-69`) rather than hardcoding "none found," so any newly-flagged allele would be caught, not assumed absent.

## 5. Tumor-vs-normal statistics

All defined once in `analyze_brca.py` and reused unmodified everywhere (BRCA HLA-A/B/C headline + per-allele + per-pattern; Phase 5's pan-cancer matched-cohort tests) so every proportion/effect-size in the project is computed the same way.

### 5a. Building blocks (`analyze_brca.py:244-292`)

- **Wilson score 95% CI** (`wilson_ci(k, n, z=1.959963984540054)`): binomial-proportion CI, well-behaved at small *n* or `k=0`/`k=n` (unlike a naive normal approximation).
- **Risk-difference CI** (`risk_difference_ci`): Wald CI on `p_tumor - p_normal`.
- **Odds ratio + Woolf-method log-OR CI** (`odds_ratio_ci`): applies a **Haldane-Anscombe +0.5 continuity correction to all four 2×2 cells whenever any cell is 0** (otherwise OR/CI would be 0 or infinite); the function reports whether the correction fired (`OR_haldane_corrected`) so it can be flagged in tables/plots.
- **Fisher exact test** (`scipy.stats.fisher_exact`) on the 2×2 carrier table for every comparison.
- **Benjamini-Hochberg FDR** (`bh_fdr`): standard BH step-up procedure, applied across every tested pattern in the detailed table (§5c).

### 5b. Headline comparison — `headline_comparison()` (`analyze_brca.py:299-348`)

For each event class (`exon5_skip`, `intron5_retention`):

- **Denominator = total distinct `Barcode`s of that `Type` in the full dataset** (not just samples with an AS event) — i.e. every tumor sample counts toward the tumor denominator whether or not it carries any event.
- Numerator = distinct carriers of that class.
- Reports Wilson 95% CI on each group's proportion, risk difference (with CI), odds ratio (with CI, Haldane-corrected as needed), and a 2×2 Fisher exact p-value, plus a plain-text `Direction` (`enriched in tumor` / `depleted in tumor` / `no difference`).
- Both the **all-alleles** and **`--exclude-alleles`-filtered** versions are always computed and saved (`table_headline_classes_all_alleles.csv` vs `table_headline_classes.csv`) — the excluded-allele mechanism changes only which events count as "this sample is a carrier," never the denominators.

### 5c. Detailed per-pattern table with FDR — `detailed_table()` (`analyze_brca.py:371-441`)

- **Denominator here is per-allele (`Contig_rd`), not per-cohort total**: for each `(Contig_rd, AS_pattern, Event_class)` combo, the tumor/normal denominator is how many samples of that `Type` carry that allele *at all* (`Tumor_denom`/`Normal_denom`) — not every patient carries every HLA allele, so this is a materially different (and correct) denominator from the headline test's whole-cohort one.
- A row is only Fisher-tested if `Total_carriers ≥ min_carriers` **(default 3, CLI `--min-carriers`)** — anything rarer is judged too underpowered to test.
- BH-FDR is applied **only across tested rows** (`FDR_q`).
- Feeds `table_volcano.csv` (`volcano_data()`, `analyze_brca.py:671-685`): log2 fold-change of Haldane-corrected tumor vs normal carrier frequency against `-log10(Fisher p)`, same `min_carriers` floor.

### 5d. Per-allele view — `per_allele_view()` (`analyze_brca.py:553-604`)

Same statistics (Wilson CI, Fisher exact) computed separately per allele with `≥ min_allele_samples` **(default 20, CLI `--min-allele-samples`)** total tumor+normal carriers, to check whether a whole-cohort effect is actually concentrated in one or two alleles. `exclude_alleles` are dropped from this view and the headline view only — never from the descriptive/overview outputs.

### 5e. Values actually used, by phase

| Parameter | HLA-A (BRCA, `analyze_brca.py` default) | HLA-B/C (BRCA, Phase 2) | Pan-cancer per-cohort (Phase 3/5) |
|---|---|---|---|
| `local_rate_threshold` | 0.10 | 0.10 (same, `phase2_bc_headline.py:80`) | 0.10 (same, `phase3_pancancer_descriptive.py:168`, `phase5_pancancer_matched_normal.py:191`) |
| `exon_skip_min_jump` | 100 bp | 100 bp (inherited, not re-tuned) | 100 bp (inherited, not re-tuned) |
| `intron_retention_max_shift` | 50 bp | 50 bp (inherited, not re-tuned) | 50 bp (inherited, not re-tuned) |
| `min_allele_samples` (per-allele view / penetrance) | 20 | 20 (`phase2_bc_headline.py:115`) | 10 for Phase 3 (`MIN_ALLELE_COHORT_SAMPLES`, `phase3_pancancer_descriptive.py:66`) and Phase 5's per-pair check (`phase5_pancancer_matched_normal.py:209`) — deliberately lowered because per-cohort Ns are much smaller |
| `min_carriers` (per-pattern Fisher/FDR/volcano) | 3 | 3 (`phase2_bc_headline.py:126,128`) | 3 (`phase5_pancancer_matched_normal.py:235`) |

## 6. Data-quality issue caught and handled: `BRCA_NORMAL` mislabeling

`data/pan_HLA-B_SJ_combined.tsv` and `data/pan_HLA-C_SJ_combined.tsv` (but not the HLA-A pan file) each contain a `Cohort == "BRCA_NORMAL"` block whose `Type` column reads `"tumor"`. Row counts for that block match the corresponding real BRCA normal export **exactly** (3,101 rows for HLA-B = `wc -l export_BRCA_normal_HLA-B.tsv`; 2,618 for HLA-C = `wc -l export_BRCA_normal_HLA-C.tsv`), which is strong evidence this is the real BRCA normal cohort with `Type` mislabeled upstream (`OVERNIGHT_LOG.md:49-65`). Per the project's "never fabricate, note and move on" rule, `Type` was **not** silently corrected. Instead:

- `phase3_pancancer_descriptive.load_pan_gene()` (`phase3_pancancer_descriptive.py:69-86`) and `phase5_pancancer_matched_normal.load_and_resolve()` (`phase5_pancancer_matched_normal.py:127-153`) both **exclude `Cohort == "BRCA_NORMAL"` entirely** before any computation.
- This loses no information: BRCA is already covered correctly by the dedicated `export_BRCA_{tumor,normal}_HLA-{B,C}.tsv` files used in Phase 2.
- Any new script touching these pan files should apply the same exclusion (`README_FOR_CLAUDE.md:22-26`).

## 7. Pan-cancer descriptive pass (Phase 3) — what it does and does not claim

`phase3_pancancer_descriptive.py`. **Explicitly descriptive — makes no tumor-vs-normal claim.** Two reasons this is enforced structurally, not just by convention: most pan-cancer cohorts are tumor-only pulls with no matched normal at all, and the one `Cohort == "NORMAL"` block that does exist is a **separate, pooled, cross-cohort normal-tissue reference** (not per-cancer-type matched normals) — so even where both tumor and `NORMAL` rows exist for a gene, treating them as a paired comparison would be invalid (`phase3_pancancer_descriptive.py:6-13`).

What it actually computes, per gene:

1. **`allele_penetrance_by_cohort()`** (`phase3_pancancer_descriptive.py:96-136`): for alleles with `≥ 10` (`MIN_ALLELE_COHORT_SAMPLES`) pan-cancer samples, finds that allele's single most-recurrent `AS_pattern` (pooled across all cohorts for a stable definition) and reports, **per `Cohort` as an independent row** (not a paired test), what % of that allele's samples in that cohort carry it.
2. **`a11_01_cross_cohort()`** (`phase3_pancancer_descriptive.py:139-157`, HLA-A only): a targeted check of whether A\*11:01's already-established BRCA-constitutive junction (`2365_2806->2383_2806`) recurs at similarly high penetrance in other cohorts / the separate normal pool. Result: recurs at 100% in the NORMAL pool (20/20), 100% in TCGA-CHOL (3/3), 85.7% in TCGA-LGG (6/7); TCGA-HNSC is an outlier at 33.3% (1/3, too small to weigh). Pooled: 30/33 (91%). This **strengthens** the constitutive-artifact read from §4c but is explicitly **not** a new significance test (no proper matched-normal denominator here — that gap is what Phase 5 fixes).

**Quarantine applied identically to Phase 2**: HLA-B's Phase 1 verdict (`untrustworthy`) means all HLA-B Phase 3 output goes under `outputs/UNVALIDATED_HLA_B_pancancer_*` and is excluded from every presented document, even though the per-cohort penetrance computation itself doesn't depend on the exon5_skip/intron5_retention classifier (gene-level quarantine, not analysis-type-level — "when in doubt, quarantine," `phase3_pancancer_descriptive.py:33-37`).

## 8. Pan-cancer matched-normal extension (Phase 5)

`phase5_pancancer_matched_normal.py`. Turns part of Phase 3's descriptive pass into a genuine matched-cohort tumor-vs-normal *test*, using `data/gdc_sample_sheet_normal_with_hla.tsv` to resolve the pooled `Cohort == "NORMAL"` block back to each sample's true TCGA project of origin via `Case ID → Project ID` (`load_sheet()` / `load_and_resolve()`, `phase5_pancancer_matched_normal.py:118-153`). Resolution rate: **145/145** pooled-`NORMAL` barcodes for the HLA-A pan file, **318/318** for HLA-B/C (0 unresolved).

- **Matched-cohort eligibility**: `matched_cohorts()` (`phase5_pancancer_matched_normal.py:156-165`) requires `≥ 3` distinct samples on **both** the tumor and (resolved) normal side (`MIN_SIDE_N = 3`). This produced: HLA-A → TCGA-CHOL (33/8), TCGA-HNSC (52/5); HLA-B/C → TCGA-CHOL (33/8), TCGA-HNSC (67/35), TCGA-KIRC (92/37). Cohorts below this floor (e.g. TCGA-THCA: 47 normal/1 tumor; TCGA-UCEC: up to 79 tumor/1 normal) or with no resolvable normal at all (TCGA-LGG, TCGA-ACC — not among the sheet's 24 projects) stay descriptive-only, exactly as Phase 3 treats them.
- **Same statistics as §5b/§5c** (`headline_comparison`, `detailed_table`) applied per `(gene, cohort)` pair via `run_pair()` (`phase5_pancancer_matched_normal.py:189-239`).
- **Pairs flagged exploratory** (`LOW_N_flag = 15`) when the smaller side's *n* is under 15, for honest caveat labeling in the write-up, not exclusion.
- **Constitutive-artifact exclusion, two layers** (`phase5_pancancer_matched_normal.py:45-64`, `108-112`, `222-227`):
  1. `KNOWN_ARTIFACT_ALLELES = {"HLA-A": ["hla_a_11_01"], "HLA-B": [], "HLA-C": []}` excluded **unconditionally in every cohort**, regardless of that cohort's own carrier count for the allele. This was added *after* a documented near-miss: an earlier version of this script re-derived the exclusion per-cohort using the same `≥10-20`-carrier-gated check as Phase 2, which **missed** A\*11:01 in TCGA-CHOL/TCGA-HNSC because only 2-3 tumor samples carry it in those small cohorts — caught by manually inspecting `table_phase5_detailed_*.csv` before write-up: 100% of HLA-A TCGA-CHOL's original "enriched in tumor" intron5_retention carriers turned out to be A\*11:01's already-known artifact pattern reappearing, not new biology.
  2. The Phase-2-style per-cohort re-derivation (§4) still runs on top, to catch any *different* constitutive allele these new cohorts might reveal. None did — HLA-C's own recurring alleles here (`hla_c_03_03`/`hla_c_03_04`) are the `real_variable_splicing_candidate` from BRCA (see below), correctly left in.
- **Result**: all 16 gene×cohort×class headline tests in Phase 5 come back null (every OR 95% CI spans 1) — reported as "a methods win (we don't need more raw BRCA normals), not a new biological result" (`PRESENTATION_NOTES.md:118-120`).
- **Bonus cross-cohort check**: HLA-C's one `real_variable_splicing_candidate` from BRCA (`hla_c_03_03`/`hla_c_03_04`, pattern `1273_1711->1291_1711`, present in tumor but resting on a single BRCA normal-side carrier) was checked for corroboration across the newly-matched cohorts (`hla_c_candidate_cross_cohort()`, `phase5_pancancer_matched_normal.py:303-323`) — pooled 42 tumor vs 2 normal carriers across BRCA+CHOL+HNSC+KIRC, directionally consistent but **not significant in any individual cohort** (all Fisher p>0.5) and not a pre-registered test — reported as "worth a dedicated follow-up," not confirmed.

## 10. Power analysis and threshold sensitivity (`additional_analyses.py`)

Not new statistics — a robustness/honesty pass on §5's headline result, reusing `analyze_brca`'s exact loading/bucketing/classification code so it cannot drift from the main analysis.

1. **Power analysis** (`power_analysis()`, `additional_analyses.py:65-102`): two-proportion z-test power via `statsmodels.stats.power.NormalIndPower`, using Cohen's *h* effect size (`proportion_effectsize`). For each headline event class, reports (a) achieved power to detect the *observed* effect at α=0.05 two-sided, and (b) the minimum detectable effect (MDE, both as Cohen's *h* and back-converted to a tumor-rate range via the arcsine-variance-stabilizing transform) that would be needed for 80% power at the actual tumor:normal sample-size ratio.
2. **Threshold sensitivity** (`threshold_sensitivity()`, `additional_analyses.py:123-153`): re-runs the full pipeline at each grid value in §9's sweep table, reporting `intron5_retention`'s headline OR/CI/Fisher-p/direction each time (the class with enough carriers to move at all).
3. **Allele frequency spectrum** (`allele_frequency_spectrum()`, `additional_analyses.py:198-239`): descriptive-only cohort background — every HLA-A allele observed, tumor/normal carrier counts, independent of the `--min-allele-samples` cutoff used elsewhere.
